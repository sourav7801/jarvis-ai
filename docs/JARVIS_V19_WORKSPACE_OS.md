# JARVIS V19 Workspace OS\n\n## Purpose\n\nV19 changes the terminal from a shared cross-market dashboard into a workspace-oriented trading operating system.\n\nThe market/data and execution safety boundaries from V17 remain authoritative. V19 adds a presentation/orchestration layer above them instead of creating a second trading engine.\n\n## Workspaces\n\n### INTRADAY\n- Session-focused chart grid\n- Signal/regime/risk context\n- VWAP / opening-range / momentum workflows\n- Paper execution guard\n- Live broker execution remains locked\n\n### SWING\n- Multi-session setup context\n- Trend, breakout, volume and catalyst surfaces\n- Position geometry separated from intraday signals\n\n### INVESTMENT\n- Long-horizon portfolio/research context\n- Allocation, valuation, fundamentals and concentration surfaces\n- No inheritance of intraday entry signals\n\n### OPTIONS\n- Dedicated V18 Options Intelligence Workbench\n- Chain, expiry, OI/IV, Greeks and paper strategy lab\n- Dedicated Options intelligence rail\n- Options data failure is isolated from chart hydration\n\n## Architecture\n\n~~~text\nBrowser\n  |\n  +-- V19 Workspace OS\n  |     +-- workspace router\n  |     +-- cockpit header\n  |     +-- context controls\n  |     +-- workspace-specific right rail\n  |     +-- unified workspace telemetry\n  |\n  +-- V18 Options Workbench\n  |\n  +-- V17 Chart/Data Runtime\n  |\n  +-- V17 HTTP / provider lanes\n  |\n  +-- FYERS / public crypto / Nautilus PAPER\n~~~\n\nV19 does not authorize live broker execution.\n\n## Unified workspace state\n\nThe browser uses:\n\n~~~text\nGET /api/v19/workspace/state?workspace=<INTRADAY|SWING|INVESTMENT|OPTIONS>\n~~~\n\nThe endpoint aggregates:\n- FYERS provider state\n- terminal health\n- PAPER autonomy state\n- Options readiness when the Options workspace is active\n\nThis avoids four independent polling loops for the cockpit.\n\n## Startup\n\nPreferred launcher:\n\n~~~powershell\ncd C:\Jarvis\ngit pull --ff-only\n.\JARVIS_V19.bat\n~~~\n\nFallback:\n\n~~~powershell\n.\JARVIS_V17.bat\n~~~\n\nThe V17 launcher remains available as a compatibility/fallback path.\n\n## Safety\n\n- JARVIS_LIVE_EXECUTION=0\n- Paper/research mode remains authoritative\n- V19 does not create broker-order endpoints\n- Workspace navigation is independent from execution lifecycle\n- Provider failures degrade the relevant data lane rather than blocking unrelated workspaces\n\n## Acceptance checklist\n\n1. Boot with JARVIS_V19.bat.\n2. Verify header identifies V19 Workspace OS.\n3. Click INTRADAY: chart workspace remains available and right rail is Intraday-specific.\n4. Click SWING: right rail changes to Swing context.\n5. Click INVESTMENT: right rail changes to Investment context.\n6. Click OPTIONS: chart grid/legacy toolbar disappears and the V18 Options Workbench occupies the center.\n7. Options right rail shows Options-specific controls rather than crypto/MCX execution content.\n8. Switch rapidly between workspaces; navigation must remain responsive.\n9. Stop/degrade FYERS; unrelated crypto/paper UI must remain usable.\n10. Verify live execution remains locked.\n\n## Rollback\n\nIf V19 UI assets are unavailable, the existing V17 launcher remains the fallback. No live execution path is enabled by V19.
